# 개인정보 및 보안 가이드

이 문서는 공공AX 업무 매크로(Series 4)를 개발, 시연, 배포하거나 녹화 결과를 공유할 때 지켜야 할 기준을 설명합니다.

이 프로그램은 화면을 녹화하면서 전역 마우스·키보드 이벤트를 수집하고, 사용자가 검토한 이벤트를 Windows 입력으로 다시 전송하는 로컬 자동화 도구입니다. 비밀번호 관리자, 보안 저장소, 접근통제 제품 또는 무인 실행을 보증하는 RPA 제품이 아닙니다.

## 가장 중요한 원칙

1. 실제 개인정보, 비밀번호, 인증번호, API 키, 업무 비밀을 입력하는 장면은 녹화하지 않습니다.
2. 영상만 보지 말고 연결된 이벤트 사이드카도 함께 검사합니다.
3. 검토하지 않은 매크로를 운영 시스템에서 실행하지 않습니다.
4. 관리자 권한은 꼭 필요한 대상 업무에서만 제한적으로 사용합니다.
5. 공유 전에는 영상, 사이드카, 복구본, 빌드 산출물과 Git 이력을 각각 확인합니다.

## 로컬에 저장되는 정보

### 녹화 영상과 프로젝트

기본 저장 루트는 Windows의 사용자 `Videos` 알려진 폴더 아래입니다.

```text
%USERPROFILE%\Videos\공공AX 업무 매크로\기록 저장소\
  YYYY\YYYY-MM\YYYY-MM-DD\
    업무시연_YYYYMMDD_HHMMSS_mmm_<임의값>.mp4
    업무시연_YYYYMMDD_HHMMSS_mmm_<임의값>.mp4.series4.json
```

사용자 `Videos` 폴더를 확인할 수 없으면 다음 위치를 대신 사용합니다.

```text
%LOCALAPPDATA%\공공AX 업무 매크로\기록 저장소\
```

영상 옆의 `*.series4.json`은 단순 설정 파일이 아닙니다. 현재 형식에는 다음 정보가 포함될 수 있습니다.

- 영상에 대한 상대 경로와 저장 시각
- 이벤트 시점, 종류, 순서와 화면 표시 문구
- 직접 입력 작업의 문자열과 키 코드·보조 키
- 마우스 휠 값
- 클릭 좌표
- 녹화 당시 캡처 영역의 위치와 크기
- 사용자 확인 경고와 기술적 실행 불가 여부·사유

최근 프로젝트를 다시 열기 위한 상태는 다음 위치에 저장됩니다.

```text
%LOCALAPPDATA%\공공AX 업무 매크로\last-project.json
```

이 파일에는 사이드카의 절대경로가 들어가므로 Windows 사용자명과 로컬 폴더 구조가 드러날 수 있습니다.

`*.ui-backup.json`, 복구 폴더, 임시 변환본도 원본 이벤트와 경로를 포함할 수 있으므로 실제 프로젝트와 같은 수준의 민감정보로 취급합니다.

### 영상이 담을 수 있는 정보

영상에는 선택한 캡처 영역 안의 모든 시각 정보가 들어갈 수 있습니다.

- 민원인·직원 이름, 연락처, 주소, 주민등록번호 등 개인정보
- 문서 제목, 파일명, 시스템명과 기관 내부 경로
- 알림 팝업, 메신저 내용, 브라우저 탭과 주소
- 로그인 화면, 일회용 인증번호, QR 코드
- 작업표시줄, 계정명, 네트워크 드라이브 이름

이벤트를 로그 목록에서 삭제해도 이미 녹화된 영상의 픽셀은 지워지지 않습니다. 영상에 민감정보가 찍혔다면 안전한 구간만 새로 만들거나 업무를 다시 시연하는 것이 원칙입니다.

## 민감 입력과 키보드 기록

녹화 중에는 캡처 영역 안의 전경 창에 전달된 키 입력이 이벤트로 기록됩니다. 비밀번호 입력 칸이라고 해서 자동으로 제외하거나 마스킹하지 않습니다.

수동 텍스트 이벤트에 전화번호, 이메일, 긴 숫자열, 주민등록번호 형태 또는 민감 키워드가 있으면 로컬 규칙으로 `민감정보 형식 의심` 경고를 표시합니다. 이 표시는 실행을 막지 않으며 영상 픽셀이나 개별 키 입력을 완전하게 판별하지도 않습니다.

화면에 비밀번호가 점으로 표시되어도 사이드카의 개별 키 조합을 통해 입력 내용을 추정하거나 재구성할 수 있습니다. 수동으로 추가한 텍스트 입력 이벤트는 문자열 자체를 저장합니다.

따라서 다음 값은 녹화 중 입력하지 않습니다.

- 비밀번호, PIN, 인증번호와 복구 코드
- API 키, 액세스 토큰, 개인키와 인증서 암호
- 주민등록번호, 계좌·카드번호, 건강정보
- 공개할 수 없는 문서 내용과 내부 시스템 식별자

민감 입력이 꼭 필요하면 녹화를 종료한 뒤 직접 처리하고, 다음 비민감 구간부터 새로 녹화합니다. 민감정보가 기록됐을 가능성이 있으면 영상뿐 아니라 사이드카, 복구본, 휴지통, 동기화 폴더와 이전 Git 커밋까지 확인합니다. 실제 자격증명이 노출됐다면 파일 삭제만으로 끝내지 말고 해당 자격증명을 폐기하거나 회전합니다.

## 공유 전 확인 목록

다른 사람에게 파일을 전달하거나 공개 Git 저장소에 올리기 전에 아래 항목을 모두 확인합니다.

- [ ] 영상을 처음부터 끝까지 재생하며 화면의 개인정보와 업무 비밀을 확인했다.
- [ ] 이벤트 목록의 입력 문자열, 키 코드, 좌표, 메시지를 확인했다.
- [ ] `*.series4.json`, `*.ui-backup.json`, `last-project.json`을 공개 대상에서 제외했다.
- [ ] 실제 녹화 영상과 화면 캡처를 공개 대상에서 제외하거나 별도로 비식별화했다.
- [ ] `recovery/`, `backup/`, 로컬 출력 폴더와 임시 파일을 제외했다.
- [ ] EXE, DLL, PDB, `bin/`, `obj/`, publish 폴더를 제외했다.
- [ ] Playwright 인증 상태, DOM 스냅샷, HAR, 브라우저 로그를 제외했다.
- [ ] `.env`, 키, 인증서, 서비스 계정 파일과 로컬 설정을 제외했다.
- [ ] Git 커밋 작성자 이름·이메일이 공개 가능한 값인지 확인했다.
- [ ] 비밀 검사 도구와 `git status --ignored`로 최종 상태를 확인했다.

이 저장소의 `.gitignore`는 실수를 줄이는 1차 방어선일 뿐입니다. 이미 Git이 추적 중인 파일이나 이전 커밋에 들어간 데이터는 `.gitignore`를 추가해도 사라지지 않습니다. 이미 공개한 비밀은 이력 정리 여부와 관계없이 먼저 폐기·회전해야 합니다. 이력 재작성과 강제 푸시는 협업자에게 영향을 주므로 백업과 사전 합의 후 진행합니다.

공개 시연 자료가 꼭 필요하면 실제 업무 녹화를 재사용하지 말고, 가상 계정·가상 문서·가상 개인정보만 있는 별도 환경에서 새로 만듭니다.

## 관리자 권한과 UAC 경계

현재 프로젝트는 관리자 권한을 자동으로 요구하도록 설정되어 있지 않습니다. 일반 사용자 권한으로 실행하는 것이 기본입니다.

Windows의 무결성 수준과 UIPI 정책 때문에 일반 권한으로 실행한 프로그램은 관리자 권한으로 실행 중인 대상 앱에 입력을 보내지 못할 수 있습니다. 이것은 정상적인 보안 경계이며 우회 대상으로 보지 않습니다.

대상 업무 때문에 관리자 권한이 반드시 필요하다면 다음 원칙을 지킵니다.

1. 배포 파일의 출처, 해시와 서명을 먼저 확인합니다.
2. 테스트 계정과 비파괴 데이터로 먼저 검증합니다.
3. 캡처 영역과 실행 시간을 최소화합니다.
4. 매크로 종료 후 프로그램도 즉시 종료합니다.
5. 관리자 권한 상태에서 웹 브라우징, 메일 확인, 비밀번호 입력을 함께 하지 않습니다.

프로그램을 관리자 권한으로 실행하면 화면·입력 제어 범위도 넓어지고 오동작의 영향도 커집니다. 관리자 권한은 매크로의 정확성이나 안전성을 보장하지 않습니다.

UAC 보안 데스크톱, 로그인 화면, 잠금 화면과 보안 자격증명 UI는 녹화·자동화 대상으로 간주하지 않습니다. UAC 승인이 필요하면 사용자가 내용을 직접 확인하고 수동으로 처리해야 합니다.

## 긴급 중지

기본 긴급 중지 단축키는 다음과 같습니다.

```text
Ctrl + Shift + F12
```

이 단축키는 다음 동작을 취소하거나 중지하는 데 사용됩니다.

- 녹화 시작 카운트다운
- 진행 중인 녹화
- 매크로 시작 카운트다운
- 진행 중인 매크로 실행

Windows 정책, 다른 프로그램의 선점 등으로 전역 단축키 등록에 실패하면 화면에 등록 실패가 표시됩니다. 이때는 프로그램의 실행 중지 버튼을 사용합니다. 실제 업무 자동화를 시작하기 전에 안전한 앱에서 단축키와 중지 버튼을 각각 시험합니다.

긴급 중지는 이미 전송된 클릭이나 키 입력을 되돌리지 않습니다. 하나의 입력 이벤트가 전송 중이면 그 이벤트가 끝난 뒤 취소가 반영될 수 있습니다. 삭제, 전송, 결재, 송금처럼 되돌리기 어려운 업무는 긴급 중지만 믿고 무인 실행하지 않습니다.

프로그램 창과 중지 버튼이 보이도록 두고, 사용자는 실행 중 자리를 비우지 않습니다.

## 경고와 실행 불가 이벤트

미완료 녹화, 영상 길이 밖 시점, 화면 범위 변화, 창 전환 키, 현재 커서 방식과 민감정보 의심 항목은 `추가 확인`으로 표시됩니다. 이 경고들은 실행을 막지 않으며, 실행 버튼을 누르면 그대로 실행 계획에 포함됩니다.

현재 구현은 드래그를 감지해 로그에 남기지만 자동 재생하지 않습니다. 마우스가 드래그 이벤트로 보고되거나 누른 위치에서 뗀 위치까지 4픽셀 이상 이동하면 종료 좌표·지속시간 데이터가 부족한 `실행 불가` 항목으로 표시합니다.

매크로 앱 자체를 조작하는 동작, 빈 payload, 부분·비정상 좌표와 긴급 중지 키 자체도 기술적 `실행 불가`에 해당합니다.

경고나 실행 불가 표시는 해당 동작이 안전하다는 인증이 아닙니다. 사용자는 다음을 직접 확인할 수 있습니다.

- 드래그가 파일 이동, 범위 선택, 스크롤바 이동 중 무엇이었는지
- 대상 앱의 현재 화면 배치와 배율이 녹화 당시와 같은지
- 일반 클릭으로 기록된 좌표가 지금도 같은 UI 요소를 가리키는지
- 실행 불가 동작을 수동 처리할지, 지원되는 여러 단계로 다시 시연할지

드래그는 현재 엔진에서 개별 실행 대상에 포함되지 않습니다. 화면 배치, DPI, 창 위치가 달라져도 다른 좌표 이벤트는 경고 후 기존 절대 좌표로 실행됩니다.

## 네트워크와 텔레메트리 경계

현재 애플리케이션 소스에는 HTTP 클라이언트, 소켓, 원격 API 호출 또는 애플리케이션 텔레메트리 전송 코드가 없습니다. 영상과 이벤트 프로젝트는 로컬 파일시스템에 저장되며, 런타임의 주요 외부 동작은 Windows 화면 녹화·전역 입력 훅·입력 전송·전역 단축키 API와 기록 폴더 열기입니다.

다만 다음 트래픽은 이 애플리케이션의 자체 업로드와 구분해야 합니다.

- 빌드·복원 중 NuGet이 패키지 피드에 접속하는 트래픽
- Windows, .NET, 백신, EDR 또는 조직 관리 도구의 자체 통신
- OneDrive 등 동기화 대상이거나 조직 정책으로 리디렉션된 `Videos` 폴더
- 네트워크 드라이브에 사용자가 직접 복사한 결과물

따라서 "로컬 저장"이 곧 "장치 밖으로 절대 나가지 않음"을 뜻하지 않습니다. `Videos`와 `%LOCALAPPDATA%`의 실제 위치, 동기화 정책, 백업 정책을 조직 환경에서 확인해야 합니다.

엄격한 폐쇄망에서는 방화벽과 네트워크 모니터링으로 실행 파일의 통신 여부를 별도로 검증할 수 있습니다. 현재 기능은 런타임 네트워크 연결을 필요로 하지 않도록 설계되어 있습니다. 다만 운영체제와 제3자 패키지까지 포함한 독립적인 무통신 인증을 의미하지는 않습니다.

## 보안 문제를 보고할 때

보안 문제를 재현하는 데 실제 녹화 영상, 사이드카, 자격증명 또는 개인정보를 공개 이슈에 첨부하지 않습니다. 가능한 경우 가상 데이터로 재현하고, 민감한 증거가 꼭 필요하면 프로젝트 관리자가 지정한 비공개 채널을 사용합니다.

사고가 의심되면 다음 순서로 대응합니다.

1. 매크로와 녹화를 중지합니다.
2. 관련 파일의 추가 공유와 동기화를 중지합니다.
