# 초보자 안내서

[README로 돌아가기](../README.md)

이 안내서는 프로그램 설치부터 메모장으로 녹화·로그 확인·실제 실행까지 설명합니다.

## 1. 설치 파일 받기

1. [최신 Release](https://github.com/obundh/gonggong-ax-local-4/releases/latest)를 엽니다.
2. Assets에서 `GonggongAX-Series4-Setup-x64-v4.0.1.exe`를 받습니다.
3. GitHub의 `Source code (zip)`은 설치 파일이 아니므로 받지 않아도 됩니다.
4. 설치 파일을 실행하고 기본 경로로 설치합니다.
5. 시작 메뉴의 `공공 AX 업무 매크로`를 엽니다.

설치 프로그램은 현재 Windows 사용자 영역에 설치하므로 정상적인 기본 설치에서는
관리자 권한이나 별도 .NET 설치가 필요하지 않습니다.

Microsoft Visual C++ x64 Runtime이 없는 PC에서는 설치 도중 Microsoft 공식
서버에서 선행 런타임을 내려받습니다. 이 Microsoft 런타임 설치에 한해서만 관리자
승인 창이 나타날 수 있습니다. 앱 자체 설치 위치는 현재 사용자 영역 그대로입니다.

설치 없이 쓰려면 `GonggongAX-Series4-Portable-x64-v4.0.1.zip`을 내려받고 새
폴더에 모두 압축 해제한 뒤 `공공AX-업무매크로.exe`를 실행하세요. ZIP 안에서
EXE만 직접 실행하거나 EXE만 따로 복사하면 네이티브 DLL이 빠져 작동하지 않습니다.
ZIP형은 Microsoft Visual C++ x64 Runtime이 이미 설치된 PC용입니다.

## 2. SmartScreen 경고가 보이면

현재 공개 설치 파일은 코드 서명 인증서로 서명되지 않았습니다. 서명되지 않은 새
파일은 Microsoft Defender SmartScreen에서 `Windows에서 PC를 보호했습니다`
또는 인식되지 않은 앱 경고를 표시할 수 있습니다.

공식 GitHub Release URL과 SHA-256을 확인해 파일을 신뢰하는 경우에만
`추가 정보(More info)` → `실행(Run anyway)`을 선택하세요. 회사 정책이나
Smart App Control이 계속 차단하면 계속 버튼이 없을 수 있습니다. 이때 보안 기능을
끄거나 정책을 우회하지 말고 IT 관리자에게 설치 승인을 요청하세요.

PowerShell에서 파일 해시를 확인하려면:

```powershell
Get-FileHash .\GonggongAX-Series4-Setup-x64-v4.0.1.exe -Algorithm SHA256
```

결과가 Release의 `SHA256SUMS.txt`와 다르면 실행하지 마세요.

## 3. 첫 화면 이해하기

- 왼쪽: 녹화 영상과 재생 조작
- 오른쪽 `현재 기록`: 이벤트 타임라인과 수동 편집
- 오른쪽 `기록 저장소`: 날짜별 과거 기록
- 화면 위쪽: 녹화 시작·종료, 매크로 실행·중지, 시작 지연 시간

처음에는 시작 지연을 `3초`로 두세요. 이 시간 동안 앱에서 메모장 같은 대상 창으로
이동할 수 있습니다. 긴급 중지는 `Ctrl + Shift + F12`입니다.

## 4. 5분 메모장 테스트

### 녹화

1. 메모장을 열어 빈 문서를 준비합니다.
2. 앱에서 시작 지연 `3초`를 선택하고 `화면 녹화 시작`을 누릅니다.
3. 메모장으로 이동해 `series4-test`를 입력합니다.
4. 문서 안을 한 번 클릭하고 휠을 한 번 움직입니다.
5. 약 5초 뒤 `-late`를 입력합니다.
6. 앱으로 돌아와 녹화를 종료하고 영상 처리가 끝날 때까지 기다립니다.

녹화 엔진이 실제 녹화 상태가 된 뒤부터 이벤트가 쌓입니다. 앱 자체를 누른 동작은
업무 매크로로 다시 기록하지 않도록 제외됩니다. 현재 녹화 범위는 주 모니터입니다.

### 영상과 이벤트 확인

1. 왼쪽에서 영상을 재생합니다.
2. 마우스 이벤트 위치와 키보드 이벤트 배너가 영상 위에 나타나는지 확인합니다.
3. 오른쪽 로그에 키보드·클릭·휠 이벤트가 있는지 확인합니다.
4. 이벤트 하나의 시간을 바꾸고 영상 위치가 함께 이동하는지 확인합니다.
5. 주황 `추가 확인`은 경고이며 실행을 막지 않습니다. 빨간 `실행 불가`만 개별 제외됩니다.

### 실제 실행

1. 메모장에서 새 빈 문서를 열고 입력할 위치를 준비합니다.
2. 앱에서 시작 지연 `3초`를 선택하고 `매크로 실행`을 누릅니다.
3. 3초 안에 메모장으로 이동합니다.
4. 기록한 텍스트·클릭·휠이 실제로 실행되고 각 이벤트에 `실행 완료`가 나타나는지 봅니다.

실행이 이상하면 `Ctrl + Shift + F12`를 누르세요. 이미 대상 프로그램이 처리한 저장,
삭제, 전송 결과는 자동으로 되돌아가지 않습니다.

## 5. 타임라인 편집하기

이벤트를 선택하면 영상이 해당 시점으로 이동하고 아래 편집기에 내용과 시간이
표시됩니다.

- 시간 수정: `시점(초)`에 `2.500`처럼 입력하고 `선택 수정`
- 순서 변경: 이벤트 오른쪽 위·아래 버튼
- 삭제: 개별 삭제 버튼 또는 선택 후 `Delete`
- 전체 삭제: 현재 이벤트를 모두 비움
- 수동 추가: 동작 종류·내용·시점을 입력하고 `새 로그 추가`

수동으로 넣을 수 있는 동작은 메모, 텍스트 입력, `Ctrl+S` 같은 키 조합,
왼쪽·오른쪽·가운데 클릭과 네 방향 휠입니다. 좌표 없이 추가한 마우스 동작은
실행 시점의 현재 커서 위치를 사용합니다.

영상 재생 속도는 검토용입니다. 배속을 바꿔도 매크로 이벤트 시간은 자동으로
재계산되지 않습니다.

## 6. 과거 기록 불러오기

1. 오른쪽 `기록 저장소`를 엽니다.
2. 날짜와 시간별 기록을 고릅니다.
3. 상태, 이벤트 수, 영상 존재 여부를 확인합니다.
4. `선택 기록 불러오기`를 누릅니다.

다른 기록으로 전환하기 전에 현재 편집 내용이 먼저 저장됩니다. 저장에 실패하면
전환을 중단합니다. 영상 파일이 없어도 실행 가능한 JSON 이벤트는 경고와 함께
실행할 수 있지만 영상 재생과 오버레이는 사용할 수 없습니다.

## 7. 저장 위치

기본 저장 위치는 Windows `비디오` 폴더 아래입니다.

```text
공공AX 업무 매크로/
└─ 기록 저장소/
   └─ 2026/
      └─ 2026-07/
         └─ 2026-07-31/
            ├─ 업무시연_....mp4
            └─ 업무시연_....mp4.series4.json
```

MP4는 화면 영상이고 `.series4.json`은 이벤트·시간·좌표·상태를 담습니다. 옮길 때는
두 파일을 함께 옮기세요. 최근 프로젝트 포인터는
`%LOCALAPPDATA%\공공AX 업무 매크로\last-project.json`에 저장됩니다.

## 8. 개인정보와 업무 파일

화면 영상과 키 입력에는 개인정보·비밀번호·업무 비밀이 들어갈 수 있습니다.
녹화 전 알림과 메신저를 닫고, 테스트 계정과 복사본 문서에서 먼저 확인하세요.
전화번호·이메일·긴 숫자열·민감 키워드는 로컬 규칙으로 경고하지만 실행을
막거나 영상을 자동 마스킹하지는 않습니다.

## 9. 자주 생기는 문제

### 실행 버튼이 켜지지 않아요

녹화 마무리나 다른 프로젝트 불러오기가 진행 중인지 확인하세요. 실행 가능한 이벤트가
하나도 없거나 모두 기술적 `실행 불가`이면 실행 버튼이 켜지지 않습니다. 미완료 기록,
영상 누락, 화면 변화와 민감정보 의심은 경고일 뿐 버튼을 끄지 않습니다.

### 좌표가 다른 곳을 클릭해요

녹화 당시와 현재의 주 모니터 위치·해상도·창 위치를 맞추세요. 화면이 달라도 앱은
경고 후 기존 절대 좌표로 실행합니다.

### 관리자 프로그램을 조작하지 못해요

Windows는 일반 권한 앱이 더 높은 권한의 창에 입력을 보내지 못하게 할 수 있습니다.
대상과 매크로 앱의 권한 수준을 맞춘 테스트 환경에서 확인하세요.

### 드래그가 실행되지 않아요

현재 드래그는 기록과 영상에는 보이지만 종료 좌표·지속시간 재생이 구현되지 않아
`실행 불가`로 표시됩니다.

### ZIP형에서 실행 오류가 나요

ZIP 전체를 새 폴더에 압축 해제했는지 확인하세요. `uiohook.dll`,
`ScreenRecorderLib.dll`, `SharpHook.dll`이 EXE와 같은 배포 폴더에 있어야 합니다.
또한 [Microsoft 공식 Visual C++ x64 Runtime](https://learn.microsoft.com/en-us/cpp/windows/latest-supported-vc-redist)이
설치되어 있는지 확인하세요. Windows N/KN에서 녹화만 실패하면 Windows 설정의
선택적 기능에서 Media Feature Pack을 설치해야 합니다.

## 10. 개발자만: 소스 빌드

소스 빌드는 Windows x64와 .NET 10 SDK가 필요합니다. 일반 사용자는 이 단계를
진행할 필요가 없습니다.

```powershell
dotnet restore .\tests\Series4.Desktop.Tests\Series4.Desktop.Tests.csproj --locked-mode
dotnet build .\Series4.Desktop.csproj -c Release -p:Platform=x64 --no-restore
dotnet test .\tests\Series4.Desktop.Tests\Series4.Desktop.Tests.csproj -c Release -p:Platform=x64 --no-restore
```

코드 구조는 [아키텍처 문서](ARCHITECTURE.md), 데이터 범위는
[개인정보 및 보안 가이드](PRIVACY_AND_SECURITY.md)를 확인하세요.
